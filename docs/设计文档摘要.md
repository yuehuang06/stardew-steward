> 作者：[姓名]

## 一、产品定位

**给谁用**：星露谷物语的休闲玩家——每天花 1-2 小时玩，不想查 wiki，不想 min-max，只想知道"今天该干嘛"。

**解决什么问题**：通用 AI 只能聊天，读不到本地存档；星露谷有 2.9MB 的 XML 存档、29 个 NPC、25 种作物、26 种鱼，通用 Agent 无法获取这些数据，给出的建议泛泛而谈。

## 二、痛点分析

| 痛点 | 通用 Agent 为什么解决不好 |
|------|--------------------------|
| 每天浇水 100+ 株作物，耗时且重复 | 通用 Agent 不能修改本地文件 |
| 不知道今天运气好不好、该下矿还是钓鱼 | 运气值在存档 XML 里，通用 Agent 读不到 |
| 忘记 NPC 生日、好感度不够 | NPC 喜好数据分散在 wiki，通用 Agent 记不准 |
| 种什么最赚钱要手算收益 | 需要交叉引用存档作物状态 + 知识库价格 + 季节天数，通用 Agent 算不对 |
| 不知道当前接了哪些任务 | 任务列表在存档 XML 的 questLog 节点，通用 Agent 看不到 |

## 三、场景定制化设计（4 项）

### 1. 存档 XML 解析器 + 知识库三层缓存
- `roxmltree` DOM 式解析 2.9MB 存档，提取资金/日期/天气/运气/作物/好感度/背包/木箱/任务
- SQLite 知识库存作物/NPC/鱼类数据，`data/*.json` 种子导入，`fetch_wiki` 在线补查
- 通用 Agent 做不到：无法读本地文件、无法持久化知识库

### 2. farm_hand 存档写入器（托管农场）
- 直接修改存档 XML：`water_all`（浇水全部作物）、`harvest_all`（收获并自动出售）、`clear_dead`（清理枯死）、`rollback_day`（回档前一天）
- 操作前自动备份 `.bak`，写回后 `roxmltree` 校验 XML 合法性，失败自动回滚
- 检测游戏进程是否运行，运行中拒绝执行
- 通用 Agent 做不到：不能写本地文件、不能安全修改游戏存档

### 3. 确定性求解器 + 校验闭环
- `auto_tasks` 根据存档状态自动生成候选任务（浇水/收获/送礼/下矿/钓鱼/采集/购物/社交/任务），按运气和天气调整优先级
- `greedy` 贪心算法在时间/体力预算内选最优任务组合
- `validator` 校验日程 JSON（资金不超支、时间不超限、至少一个 must 任务），不通过自动回传 LLM 重试
- 通用 Agent 做不到：LLM 无法可靠完成 54×50g 这类乘法、无法在上下文里做全局最优排序

### 4. context_length 截断 + thinking_mode
- `build_messages()` 按配置的 context_length 估算 token（chars/3），保留 system 消息 + 最近 N 条历史，tool_call/tool 响应对保证不被拆散
- thinking_mode 为 true 时在请求体加 `{"thinking":{"type":"enabled"}}`
- 通用 Agent 做不到：不暴露这些参数，无法精细控制上下文窗口

## 四、系统架构

```
用户交互层
  CLI (rustyline)           Tauri 2 桌面窗口 (React 18)
  CliReporter (println)     TauriReporter (emit 事件)
           \              /
            \            /
        stardew_steward 核心库 (Rust)
        ├── Agent Loop (LLM ↔ 工具调用循环)
        ├── Parser (roxmltree XML → GameState)
        ├── Knowledge (SQLite + fetch_wiki)
        ├── Tools (8 个: read_save, query_knowledge,
        │          solve_schedule, auto_schedule,
        │          fetch_wiki, crop_advisor,
        │          gift_finder, farm_hand)
        ├── Solver (贪心 + auto_tasks)
        ├── Validator (校验闭环)
        ├── Usage (per-session token 统计)
        └── Session (JSON 持久化)
```

## 五、技术选型

| 模块 | 关键 crate | 理由 |
|------|-----------|------|
| 存档解析 | roxmltree | DOM 式，路径导航深嵌套 XML |
| 知识库 | rusqlite (bundled) | 内嵌编译，无需系统 SQLite |
| HTTP | reqwest (rustls-tls) | 纯 Rust TLS，WSL/Windows 通用 |
| GUI 后端 | tauri 2 | Rust 后端直接复用核心库 |
| GUI 前端 | React 18 + Vite 5 | 组件化，@tauri-apps/api 通信 |
| CLI | clap + rustyline | 类型安全参数 + 行编辑 |

## 六、R1-R6 对照

| 要求 | 实现 |
|------|------|
| R1 Rust 核心 | 全部业务逻辑在 Rust，CLI 和 GUI 共用 `[lib]` |
| R2 界面 | CLI 终端 + Tauri 像素风桌面窗口（竖向时间线日程卡片、打字机效果、9-slice border-image） |
| R3 可配模型 | GUI 设置面板 + `%APPDATA%/config.toml`，可配 endpoint/key/model/context_length/thinking_mode/价格/Token预算 |
| R4 进度+打断 | ProgressReporter trait，CLI 用 println，GUI 用 emit 事件 + 像素进度条；Ctrl-C / 停止按钮 → AtomicBool |
| R5 历史管理 | 会话 JSON 持久化（自动保存/加载/删除），Agent 工作轨迹导出 |
| R6 Token 统计 | per-session 统计，预算可配，超限自动中断 |

## 七、8 个专用工具

| 工具 | 类型 | 通用 Agent 能否做到 |
|------|------|-------------------|
| read_save | 读本地存档 | ✗ |
| query_knowledge | 查 SQLite 知识库 | ✗ |
| auto_schedule | 自动生成日程 | ✗（需读存档+知识库+求解器） |
| farm_hand | 写存档（浇水/收获/回档） | ✗ |
| crop_advisor | 作物收益对比 | ✗（需交叉引用存档+知识库） |
| gift_finder | 送礼推荐 | ✗（需扫背包匹配 NPC 喜好） |
| solve_schedule | 手动求解 | ✗ |
| fetch_wiki | 在线查 wiki | △（通用 Agent 也能搜，但无结构化提取） |
